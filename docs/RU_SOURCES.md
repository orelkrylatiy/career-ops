# Российские источники вакансий в автономном CareerOps

**Статус:** интеграция в PR #6 (18.11.2026). Список отражает **наличие кода и подключение источников**, а не гарантирует актуальность API, наличие вакансий или успешность откликов.

## 1. Матрица платформ

| Площадка | Источник вакансий | Модуль в репозитории | Как выполняется отклик | Что ещё требуется |
| --- | --- | --- | --- | --- |
| **Хабр Карьера** | Публичное серверное состояние страницы поиска | `providers/habr-career.mjs` | Через Playwright и аккаунт кандидата | Настоящий браузерный тест, проверка авторизации и подтверждения отправки |
| **GeekJob** | Публичный JSON-поиск | `providers/geekjob.mjs` | Через реальную форму на сайте | Проверить актуальность JSON, регистрацию и DOM подтверждения |
| **SuperJob** | HTML/структурированная разметка поиска | `providers/superjob.mjs` | Через браузер | Подтвердить текущую разметку и ограничения доступа |
| **getmatch** | Запись в `catalog/source-catalog.yml` | **Отдельного готового провайдера нет** | Возможно только при ручном/дополнительном источнике вакансий | Нужны полноценный discovery-адаптер и браузерные тесты |
| **Работодатели с Greenhouse, Lever, Ashby, Workday, iCIMS и др.** | Upstream ATS-каталоги | Набор `providers/*` оригинального CareerOps | Отдельная веб-форма компании | Доступность для кандидата, состояние формы и авторизация |
| **Huntflow, Potok, Skillaz, Talantix** | Специализированных адаптеров в данной интеграции нет | **Не добавлены** | Универсальный браузерный агент может встретить страницу, но поддержки не гарантировано | Нужен анализ вакансий и механизмов отклика |
| **HeadHunter (.ru, .kz, .uz)** | Исключён из автономного режима | Не используется как источник автопилота | **Не отправляется** | Так задумано — отдельный продукт |
| **Telegram** | Источник исключён из автономного сканирования | У upstream остался неактивный `telegram-channel` | **Не используется** | Так задумано — не нужен Telegram |

В объединённой ветке присутствует много upstream-провайдеров; не трактуйте количество файлов в `providers/` как количество протестированных способов отклика.

## 2. Как российский источник попадает в очередь

### Шаг 1 — конфигурация

Код читает собственные источники из `portals.yml`. Также есть региональный каталог `catalog/source-catalog.yml` с `country: RU`, где среди прочего есть источники:

- `ru-habr-career` → `habr-career`;
- `ru-geekjob` → `geekjob`;
- `ru-superjob` → `superjob`;
- `ru-getmatch` → только запись о сайте, без собственного провайдера.

В каталоге также есть справочник российских IT-компаний (CNews500), используемый модулем регионального реестра. Содержимое справочников может устаревать — сам факт регистрации компании не гарантирует актуальную страницу вакансий.

### Шаг 2 — активация

Ранний вариант форка содержал перечисленные провайдеры, но **не добавлял их автоматически в текущий запуск**. В PR #6 это исправлено:

~~~bash
node source-registry.mjs export --country RU
~~~

Команда объединяет подходящие записи каталога с настроенными источниками и формирует локальный файл:

~~~text
data/portals-regional.generated.yml
~~~

При обычном `npm run autopilot` runner выполняет этот экспорт и сканирует получившийся файл через `autopilot-scan.mjs`.

### Шаг 3 — широкий ATS-поиск

Отдельно запускается обратный поиск по источникам ATS. Это не поиск по HeadHunter и не подключение Telegram. Интервал по умолчанию — 14 дней; слишком широкий обход может быть ресурсоёмким.

### Шаг 4 — очередь и отправка

`scan.mjs`, `scan-ats-full.mjs` записывают найденное в `data/pipeline.md`. Затем `autopilot.mjs` приводит записи к единому виду, проверяет дубли и чёрные списки, назначает приоритет и пишет задачи в SQLite.

**API и HTML-парсеры используются для обнаружения вакансий, а не для отправки заявок.** Отправка выполняется отдельным агентом в авторизованном Chromium через Playwright CLI. На таких сайтах, как Хабр Карьера или SuperJob, авторизация может быть существенной частью процесса.

## 3. Команды настройки

Первые проверки:

~~~bash
# При настроенных portals.yml и данных кандидата
npm run autopilot:preflight
node source-registry.mjs status --json
node source-registry.mjs export --country RU

# Сканирование текущего каталога, создаёт/дополняет локальный pipeline
CAREER_OPS_PORTALS="$PWD/data/portals-regional.generated.yml" node autopilot-scan.mjs

# Безопасный просмотр очереди — новые сайты не открываются и отклики не отправляются
npm run autopilot:dry-run
npm run autopilot:status
~~~

Полное обновление регионального реестра (с обращениями к сайтам справочников и компаний) — отдельная, более затратная операция:

~~~bash
node source-registry.mjs full --country RU
~~~

В автономном режиме она запускается только при явном флаге:

~~~bash
npm run autopilot -- --agent codex --max-jobs 3 --refresh-registry
~~~

Если справочник или конкретный сайт недоступен, региональный поиск может частично пропустить источники; остальные направления сканирования выполняются отдельно.

## 4. Управление объёмом поиска

~~~bash
# По умолчанию региональные источники RU включены
# Отключить только региональный каталог:
export AUTOPILOT_REGIONAL=off

# Запретить широкий ATS-поиск, сохранив свои компании и RU:
export AUTOPILOT_DISCOVERY=configured

# Ограничить историю ATS-поиска семью днями:
export AUTOPILOT_ATS_SINCE_DAYS=7

# Пропустить все новые сканы и взять ранее собранные вакансии:
npm run autopilot -- --agent codex --no-scan --max-jobs 3
~~~

Параметр `AUTOPILOT_DISCOVERY=configured` не означает «только portals.yml»: **региональный каталог продолжает работать**, если `AUTOPILOT_REGIONAL` не установлен в `off`.

Не используйте устаревший `--wide`. Теперь «широкий поиск» создаётся временной конфигурацией внутри `autopilot-scan.mjs`. Предпочтения по зарплате/стеку/локации влияют на приоритет, а не вычёркивают вакансию; явные blacklist и проверка допустимости URL остаются.

## 5. Ограничения реальных откликов

- На российской площадке может потребоваться заранее авторизованный аккаунт. Переиспользование личного браузерного профиля допустимо только для владельца учётной записи.
- Изменения HTML или JSON сайта могут нарушить сбор вакансий без ошибок на других источниках.
- Нестандартные вложения, регистрация, обязательные поля или CAPTCHA могут блокировать отдельную заявку.
- Письма подтверждения могут обрабатываться через Gmail OAuth, но не через Telegram и не через HeadHunter.
- Поддержка отдельной ATS не равна доказательству, что её публичный API разрешает отправку откликов.
- Для некоторых работодателей потребуются согласия и юридически значимые действия, которые агент не должен выдумывать или выполнять без надлежащего разрешения.

## 6. Что необходимо проверить перед объявлением «работает»

**Нет подтверждённого production E2E** для Хабр Карьеры, GeekJob или SuperJob в этой ветке. Для каждой площадки следует выполнить отдельный тестовый сценарий с разрешённым аккаунтом: получение свежих вакансий → переход на карточку → открытие формы → заполнение достоверных данных → отправка → реальная страница подтверждения → запись `applied` в трекер. Проверить, что `submitted_unconfirmed` и `captcha` **не приводят к дублю**.

Пока нет этого протокола и зелёного CI, корректная оценка — **реализована интеграционная основа, не подтверждена эксплуатационная надёжность**.
