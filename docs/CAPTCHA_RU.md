# CAPTCHA в автономном CareerOps — реализация, провайдеры и пределы

**Версия документа:** интеграционная ветка PR #6 (18 ноября 2026 года). Это описание исходников `captcha-solver.mjs` и `autopilot-runner.mjs`, а не обещание гарантированного прохождения проверки на любом сайте.

[Общее руководство](./AUTOPILOT_RU.md) · [Российские площадки](./RU_SOURCES.md) · [Инструкция для агента](../modes/autopilot.md)

## 1. Какие проверки распознаются

| Проверка | Текущее поведение | Что реально реализовано |
| --- | --- | --- |
| Изображение с текстом/цифрами | Автоматическое обнаружение, OCR, ввод ответа | Да, через vision-модель |
| Кириллическая текстовая CAPTCHA | Нормализация распознанной русской строки и ввод | Да, зависит от качества OCR и сайта |
| reCAPTCHA / hCaptcha / Turnstile | Обнаружение стороннего виджета, статус блокировки | Нет универсального автоматического решения |
| SmartCaptcha и другие поведенческие системы | Может остаться препятствием, зависит от конкретной страницы | Специализированная интеграция отсутствует |
| Email OTP / magic link | Чтение свежего письма в отдельной Gmail-утилите | Только при настроенном Gmail OAuth |
| SMS / MFA / 2FA / KYC | Регистрируется препятствие отдельной вакансии | Не обходится |

**«MGS-решение» в коде не найдено.** Ни пакета, ни адаптера, ни интеграции под названием MGS нет. В реализованной системе используется **vision OCR** — AI-модель распознаёт текст с изображения. Это не сервис распознавания любой CAPTCHA и не гарантия решения сложной проверки.

## 2. Пошаговый путь

~~~text
Браузерный агент открыл форму
       ↓
captcha-solver detect в той же Playwright CLI session
       ↓
текстовая CAPTCHA обнаружена?
  ├─ нет → продолжить обычный сценарий
  ├─ сторонняя интерактивная проверка → пометить вакансию как captcha
  └─ да
       ↓
снимок картинки + локальный артефакт
       ↓
OpenCode (модель уже настроена локально)
       ↓ если OpenCode недоступен или завершился ошибкой
OpenAI-compatible API, если задан OPENAI_API_KEY
       ↓
очистка и проверка текста ответа
       ↓
ввод в реальное поле формы
       ↓
проверка обычной реакции страницы
  ├─ принято → продолжить анкету
  └─ отклонено → ещё попытка в пределах лимита
       ↓
неразрешённая проверка → captcha для вакансии → следующая вакансия
~~~

Сервер не создаёт вторую браузерную сессию специально для CAPTCHA. Модуль использует `AUTOPILOT_BROWSER_SESSION` / `--session` для обращения к той же авторизованной вкладке, где агент заполняет форму.

## 3. Подключение OpenCode

Первый OCR-провайдер — **OpenCode CLI**. Настройте и авторизуйте OpenCode самостоятельно, а также выберите модель, способную принимать изображения.

~~~bash
opencode --version

# Вариант A — использовать модель, настроенную по умолчанию в OpenCode
unset CAPTCHA_OPENCODE_MODEL

# Вариант B — явно задать ID подходящей модели из ВАШЕЙ конфигурации
export CAPTCHA_OPENCODE_MODEL="provider/your-vision-model"

# При необходимости указать путь к бинарнику
export CAPTCHA_OPENCODE_COMMAND="opencode"
~~~

Если указано несколько моделей через запятую, код пробует их по очереди:

~~~bash
export CAPTCHA_OPENCODE_MODEL="provider/vision-primary,provider/vision-fallback"
~~~

**Важно:** не копируйте условные `provider/your-vision-model` как действующий идентификатор. Список доступных моделей зависит от настроенного в OpenCode провайдера. В текущей версии **нет жёстко прописанной обязательной модели**.

## 4. Резервный OpenAI-совместимый vision API

При ошибке OpenCode код может отправить PNG в API с совместимым маршрутом `/chat/completions`. Для этого требуются действующие параметры:

~~~bash
export OPENAI_API_KEY="<секретный API-ключ>"
export OPENAI_BASE_URL="https://api.openai.com/v1"
export CAPTCHA_VISION_MODEL="<ID модели, поддерживающей изображения и chat completions>"
~~~

Актуальный допустимый ID модели узнавайте в документации выбранного провайдера; из кода нельзя заключить, что любой идентификатор будет поддерживаться. По умолчанию в коде также предусмотрено поле `OPENAI_MODEL` и резервное значение, но разумнее указать проверенную модель явно.

**Приватность:** API-провайдер получает изображение CAPTCHA. Картинки и результаты распознавания сохраняются локально в `data/autopilot/captcha/<profile>/<flow>/`. Это может быть конфиденциальный пользовательский материал; не публикуйте файлы и не загружайте их в Git.

## 5. Попытки и поведение при ошибках

По умолчанию агент просит **5 попыток**, сам решатель ограничивает максимум **8**. Для одного запуска:

~~~bash
export AUTOPILOT_CAPTCHA_ATTEMPTS=5
# Только после отдельного возобновления кампании и выбора CAREER_OPS_ROOT
AUTOPILOT_LIVE=1 npm run autopilot:live -- --agent codex --max-jobs 3
~~~

Прямое использование на **уже открытой** сессии Playwright:

~~~bash
node captcha-solver.mjs detect --session career-ops-worker-0 --json
node captcha-solver.mjs solve --session career-ops-worker-0 --flow apply --attempts 5 --json
~~~

Для диагностики отдельного изображения:

~~~bash
node captcha-solver.mjs ocr ./example-captcha.png --json
~~~

`detect` информирует о типе проверки; сама команда **не отправляет форму вакансии**. `solve` пытается заполнить обычное текстовое поле и определить, принято ли значение. Если проверка недоступна, сторонняя или все попытки исчерпаны, команда возвращает неуспех.

Работа по вакансии после такого препятствия может быть завершена статусом `captcha`. **Весь автопилот не ждёт человека и продолжает очередь.** Если результат реальной отправки неоднозначен, немедленный повтор противопоказан: возможен дубль.

## 6. Чем это отличается от «автопрохода любой CAPTCHA»

Распознавание текста — только один из возможных механизмов проверки человека. Наличие распознавателя изображений **не** означает автоматическую поддержку:

- устройств или браузерных аттестаций;
- невидимой оценки риска;
- интерактивного выбора объектов в стороннем виджете;
- проверки по SMS, MFA, электронной подписи или внешнему аккаунту;
- механизмов, которые запрещают автоматические попытки.

Автопилот не должен подменять токены проверки, имитировать подтверждение, запускать неразрешённые сторонние сервисы или выдавать ошибочный отклик за успешный.

## 7. Состояния и проверка фактической отправки

Разделяйте **CAPTCHA принята** и **отклик подтверждён**. После успешного прохождения текстовой проверки агент всё равно обязан закончить форму и выполнить:

~~~bash
node autopilot-verify.mjs begin "<job-url>" --session career-ops-worker-0
# Нажать Submit в реальном браузере
node autopilot-verify.mjs finish "<receipt-path>"
~~~

И только после проверенного события возможно `node autopilot.mjs report ... applied --channel browser --evidence ...`.

Не путайте `captcha` (препятствие), `validation_failed` (ошибка полей) и `submitted_unconfirmed` (возможная отправка без доказанного успеха). В последнем случае повторная отправка запрещена до разбора результата.

## 8. Что проверено

В PR присутствуют модуль OCR и контрактные тесты нормализации ответа и распознавания формы; код проверен статически. **Полный запуск тестов и настоящий end-to-end прогон со сторонними CAPTCHA не подтверждены.** Для боевого использования проведите отдельный тест на разрешённой локальной форме, затем ограниченный сценарий на реальном работодателе без нарушения правил сайта.
