## 1. Что делает система

Отдельный явно запущенный автопилот способен находить вакансии, оценивать приоритет, выбирать резюме, открывать реальную форму в Chromium, вводить достоверные данные кандидата, отправлять заявку **без запроса подтверждения на каждом шаге** и проверять результат отправки.

~~~text
portals.yml + каталог RU + международные ATS
      ↓  scan.mjs / scan-ats-full.mjs через autopilot-scan.mjs
data/pipeline.md
      ↓  автопилот: дедупликация + blacklist + приоритет 0–100
SQLite (data/autopilot.db, очередь и аренды вакансий)
      ↓  отдельный coding agent на одну вакансию
Playwright CLI (сохранённая сессия Chromium)
      ↓  резюме, правдивые ответы, Gmail OTP при наличии доступа
      ↓  текстовая CAPTCHA через vision при необходимости
autopilot-verify.mjs (состояние DOM + URL + сеть)
      ↓
applied / submitted_unconfirmed / captcha / validation_failed / failed / skipped
      ↓
история, отчёты, аналитика
~~~

У обычных режимов upstream `apply` / `email` / веб-предпросмотра подтверждение человеком **сохранено**. Без подтверждения отправляет **только отдельно запущенный** `npm run autopilot`. Ни HeadHunter, ни Telegram не входят в эту автономную цепочку.

## 2. Установка на Linux или VPS

Требуется Node.js версии, подходящей под `package.json` (>=22.13 в ветке на дату написания, при этом диапазон движка точнее указан в самом файле). Для сборки нативной SQLite-зависимости может потребоваться компилятор; для браузера нужны системные библиотеки Chromium. Не запускайте это от root и не выдавайте агенту доступ к домашней директории с посторонними ключами.

~~~bash
git clone https://github.com/orelkrylatiy/career-ops.git
cd career-ops
git fetch origin
git switch feat/upstream-1-40-autonomous-20261118

node --version
npm install
npx playwright install --with-deps chromium
npm run doctor
~~~

Для работы нужен один авторизованный CLI: `codex`, `claude` или `opencode`. В `auto`-режиме выбор происходит в порядке Claude → Codex → OpenCode по наличию исполняемой команды; наличие бинарника **не означает**, что выполнен вход — перед началом откликов исполнитель делает отдельную проверку доступа к модели.

**Учётные данные и резюме хранятся локально**, а не в Git. Перед первым запуском настройте `config/profile.yml`, `portals.yml`, `cv.md` и подготовленный PDF. Команда `npm run autopilot:preflight` проверяет наличие адреса кандидата, PDF и Playwright CLI. Телефон пока считается предупреждением, если другие условия соблюдены.

Для резюме нужен существующий файл в `output/` либо `data/` и настройка `autopilot.resumes` в `config/profile.yml`; также поддерживается устаревшее поле `autopilot.cv_pdf`. Проверка:

~~~bash
node autopilot-resume.mjs validate
node autopilot-resume.mjs select --title "Backend Engineer" --json
~~~

Не копируйте демонстрационные имя, email, опыт, ссылки или достижения из `config/profile.example.yml` в настоящие отклики.

## 3. Безопасная проверка и запуск

~~~bash
# Проверки без отправок
npm run autopilot:test
npm run autopilot:preflight
npm run autopilot:dry-run

# Первые 1–3 отклика на подготовленной машине
npm run autopilot -- --agent codex --max-jobs 3

# Полный проход по очереди
npm run autopilot -- --agent codex
~~~

Опции **именно браузерного исполнителя**:

| Опция | Значение |
| --- | --- |
| `--agent auto\|codex\|claude\|opencode` | Выбор агента; по умолчанию `auto`. |
| `--max-jobs N` | Не больше N выданных из очереди вакансий за один запуск. |
| `--timeout-minutes N` | Ограничение времени одного агента, 1–110 минут, по умолчанию 25. |
| `--no-scan` | Пропустить поиск, обрабатывать уже существующую очередь. |
| `--refresh-registry` | Полностью обновить региональный реестр и принудительно выполнить широкий ATS-поиск. |
| `--dry-run` | Просмотр очереди без браузера, захвата вакансий и отправок. |

`npm run autopilot:dry-run` **не запускает новый поиск по интернету** — это проверка имеющегося `data/pipeline.md`. Для отдельного сканирования существует `node autopilot-scan.mjs`, но оно может обращаться к сетевым сайтам и менять локальный pipeline, поэтому не путайте его с dry-run.

Сканеры и менеджер очереди находятся в разных командах: `node autopilot.mjs` **не отправляет** вакансии сам по себе. Не запускайте одновременно два автономных исполнителя с **одной и той же браузерной сессией**.

## 4. Источники вакансий и российский рынок

При обычном запуске идут три независимых направления:

1. Настроенные источники и компании из `portals.yml`.
2. Российский каталог `catalog/source-catalog.yml`: `source-registry.mjs export --country RU` формирует `data/portals-regional.generated.yml`, затем этот файл сканируется через `autopilot-scan.mjs`.
3. Широкий обход каталогов ATS через `scan-ats-full.mjs` (по умолчанию за 14 дней, максимум 30 в параметре исполнителя).

На сегодня региональный каталог содержит явные модули поиска для **Хабр Карьеры, GeekJob, SuperJob**. Getmatch присутствует в каталоге, но собственного готового провайдера поиска для него нет. Отдельных модулей для Potok, Huntflow, Skillaz, Talantix нет. Сайты компаний с Greenhouse/Lever/Ashby/Workday и т. п. ищутся через upstream ATS-провайдеры. **Модуль поиска не равен доказанному автоматическому отклику**: анкеты открываются и заполняются браузером, а для некоторых потребуется существующая авторизация.

Настройки окружения:

~~~bash
# Отключить региональный каталог RU, оставить остальные источники
export AUTOPILOT_REGIONAL=off

# Отключить только широкий ATS-поиск; RU-каталог продолжает сканироваться
export AUTOPILOT_DISCOVERY=configured

# Изменить окно широкого ATS-поиска, 1–30 суток
export AUTOPILOT_ATS_SINCE_DAYS=7

# Полностью обновить региональный реестр при запуске
npm run autopilot -- --agent codex --refresh-registry --max-jobs 3
~~~

Важная особенность: `autopilot-scan.mjs` передаёт **временный YAML** в оригинальные сканеры и снимает предпочтительные фильтры. Поэтому вакансии с менее подходящей зарплатой, стеком или локацией могут попасть в очередь с более низким приоритетом. Чёрные списки, проверка публичного URL и дедупликация продолжают действовать. `--wide` старой версии больше не используется.

Подробнее — [таблица площадок и ограничений](./RU_SOURCES.md).

## 5. Работа браузера на сервере

Playwright CLI использует **именованную постоянную сессию**, где сохраняются авторизованные аккаунты, cookie и данные браузерного профиля. По умолчанию Chromium стартует **без интерфейса**; X-сервер для обычного запуска не нужен.

~~~bash
# Режим VPS без окна (значение по умолчанию)
npm run autopilot -- --agent codex --max-jobs 1

# Видимый Chromium для диагностики с графической сессией
AUTOPILOT_BROWSER_HEADED=1 npm run autopilot -- --agent codex --max-jobs 1
~~~

Для независимых направлений карьеры используйте `node profile.mjs`: каждый профиль получает свой `CAREER_OPS_ROOT`, `AUTOPILOT_WORKER_ID`, `AUTOPILOT_BROWSER_SESSION`. Не делите один браузерный профиль между разными кандидатами.

ВНИМАНИЕ. Сейчас coding agent запускается с **широкими разрешениями в локальной среде** (`danger-full-access` для Codex, аналогичный неинтерактивный режим у других CLI). Запускайте его только в выделенном окружении с минимальными правами и без доступа к посторонним ключам, репозиториям и данным. Страницы вакансий и письма могут содержать недоверенные инструкции и не должны определять действия агента.

## 6. CAPTCHA и подтверждение почты

Для обычной текстовой CAPTCHA предусмотрена цепочка «обнаружить изображение → получить ответ vision-модели → ввести текст → проверить реакцию страницы». Сначала используется уже настроенный OpenCode, затем — OpenAI-совместимый API, если заданы ключ и модель. По умолчанию запрашивается 5 попыток, предел — 8.

~~~bash
# Только при уже работающей Playwright-сессии
node captcha-solver.mjs detect --session career-ops-worker-0 --json
node captcha-solver.mjs solve --session career-ops-worker-0 --flow apply --attempts 5 --json
~~~

Код **не реализует гарантированное решение** reCAPTCHA, hCaptcha, Turnstile, SmartCaptcha, вторых факторов и проверок устройства. Неразрешённая CAPTCHA ставит препятствие **конкретной вакансии**, а не прекращает весь цикл. Кодового провайдера с названием «MGS» в проекте нет. См. [разбор CAPTCHA и настроек моделей](./CAPTCHA_RU.md).

Email OTP / magic link выполняется отдельной утилитой `autopilot-mail.mjs` с Gmail OAuth:

~~~bash
node autopilot-mail.mjs doctor
# --since — текущие секунды Unix непосредственно перед запросом письма
node autopilot-mail.mjs wait --domain careers.example.org --url-host careers.example.org --since 1795000000
~~~

**Число в примере фиктивное**: всегда подставляйте актуальный `date +%s` перед отправкой письма. Нужны `GMAIL_CLIENT_ID`, `GMAIL_CLIENT_SECRET` и `GMAIL_REFRESH_TOKEN`. Если доступ к почте отсутствует, регистрация или письмо-подтверждение могут остаться незавершёнными; автопилот продолжит другие вакансии.

## 7. Как подтверждаются отправки

Перед настоящим Submit исполнитель делает `autopilot-verify.mjs begin`; затем `finish` оценивает DOM, ошибки формы, URL, сетевые признаки и следы действий. Только подтверждённое событие может получить `applied` и попасть в счётчик и Markdown-трекер.

| Состояние | Смысл | Автоматический повтор |
| --- | --- | --- |
| `queued` | Ждёт своей очереди. | Да, когда придёт очередь. |
| `claimed` | Взята одним исполнителем на время аренды. | Нет до завершения/разбора аренды. |
| `applied` | Успех подтверждён верификатором. | Нет. |
| `submitted_unconfirmed` | Отправка могла состояться, но успех не доказан. | **Нет**, опасность дубля. |
| `captcha` | Проверку сайта не удалось завершить. | Не повторять автоматически в том же запуске. |
| `validation_failed` | Анкета не принята валидацией. | После исправления данных/условий. |
| `failed` | Ошибка при попытке. | По правилам повторов и только при доказанном отсутствии отправки. |
| `skipped` | Вакансия сознательно пропущена. | Нет в текущем проходе. |

Если один агент упал, обработка других вакансий обычно продолжается; три последовательных сбоя агента приводят к остановке всего запуска. Истёкшие «захваты» вакансий карантинируются, а **не** просто возвращаются в очередь, так как Submit уже мог произойти.

Для мониторинга:

~~~bash
npm run autopilot:status
node autopilot.mjs analytics
node autopilot.mjs logs --limit 50
~~~

Данные находятся внутри корня кандидата: `data/autopilot.db`, `data/autopilot-queue.md`, `data/autopilot/logs/`, `data/autopilot/evidence/` и `data/autopilot/reports/`. Снимки браузера, скриншоты и trace могут содержать персональные данные, поэтому не публикуйте их.

## 8. Что подтверждено и что ещё требует проверки

**Подтверждено по исходникам и точечным контрактным проверкам:** исходники upstream в интеграционной ветке, модуль очереди, явное подключение RU-каталога, исключение HH/Telegram из автономного сканирования, сохранённые браузерные сессии, логика отчётных статусов и распознавание текстовых CAPTCHA.

**Не подтверждено полноценным прогоном:** успешная установка нативных зависимостей на вашем Linux/VPS, полный `npm run autopilot:test`, завершение browser E2E, Gmail OAuth на реальном аккаунте, рабочие регистрации и успешные отправки на Хабр Карьере / GeekJob / SuperJob. Проверка GitHub Actions по PR #6 на момент аудита показывала **0 запусков**. Нельзя утверждать, что всё прошло проверку.

Перед слиянием нужны зелёные CI, тест браузера на локальной фикстуре и ограниченный однократный сценарий на разрешённом сайте. **Не объединяйте PR с main только на основании синтаксического аудита.**

## 9. Обновление системы

Ветка содержит upstream CareerOps 1.40.0, но форк использует дополнительный автопилот и свои скрипты. Встроенный `update-system.mjs apply` защищён от перезаписи этих модулей. Следующие обновления исходного проекта нужно переносить через отдельную ветку, ревью и PR, а не прямым запуском `npm run update`.

Технические детали и список известных ограничений — [UPSTREAM_AUTONOMOUS_MIGRATION.md](./UPSTREAM_AUTONOMOUS_MIGRATION.md).
